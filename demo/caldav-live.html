Careful: what you type here is stored in clear text — by default in sessionStorage, so a reload keeps the connection but closing the tab forgets it. Tick remember on this device and it goes into localStorage as well: readable by every script on this origin — on a shared host such as GitHub Pages that covers every other page served from it — and it survives a browser restart. Unlike an API token a password cannot be revoked server-side, so use a read-only or app-specific account, and prefer a server that issues app passwords. “Disconnect” only forgets it locally.

The URL is the CalDAV entry point — the server root, your principal or the calendar home all work, since discovery follows current-user-principal → calendar-home-set from wherever it starts. Authentication is HTTP Basic, so an app-specific password is the right credential where the server offers one. The credentials are only stored after discovery has actually returned calendars — see the note above for where they end up. Cross-origin: a browser sends an OPTIONS preflight before every PROPFIND/REPORT, and the server must answer it without demanding authentication, listing PROPFIND and REPORT in Access-Control-Allow-Methods and Authorization, Depth, Content-Type in Access-Control-Allow-Headers. Requests go out with credentials: 'omit', so a wildcard Access-Control-Allow-Origin is enough. Most servers fail that preflight (they answer it with 401) — for those, run a same-origin forwarder and put its prefix in Proxy; the absolute target URL is appended URL-encoded, so /dav-proxy?url= becomes /dav-proxy?url=https%3A%2F%2F….

Every calendar discovered under your principal is listed above; Ctrl/⌘-click picks individual ones. Each selected calendar becomes one lane of the gantt renderer, and the number in brackets is how many events it contributes to the currently fetched window. Deselecting a calendar costs no request, and reselecting one is served from the events already held for this window — only a calendar that has never been fetched for the current window triggers a REPORT. Panning and zooming refetch only once the viewport leaves the window that was fetched (50 % wider than the view on either side), and a response that arrives after you have moved on is dropped. Recurring events are expanded server-side via <C:expand> — caldav.js deliberately implements no RRULE engine, so a server that ignores expand shows only the master event.
